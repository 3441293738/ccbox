# CCBOX

**给 Claude Code 配一个独立开发空间：选账号、选项目，打开就用。**

CCBOX 是 Windows 与 Apple Silicon Mac 上的图形化 Docker 工作区管理工具。
它将 Claude Code、授权浏览器与桌面 VS Code 放在容器内，管理各空间的项目挂载、代理与持久化数据；需要已有 JDK、Maven、Node 等工具时，可显式开启本机开发。

> 非 Anthropic、Microsoft 或 Docker 官方产品。需要自己的有效账号及相关服务使用资格。本项目不保证匿名性、账号状态或绝对隔离。

## 下载与开始

- [下载已打包版本](https://github.com/3441293738/ccbox/releases)：Windows x64 / macOS ARM64（M 系列）。
- [使用指南](docs/使用指南.md) · [架构与边界](docs/架构与边界.md) · [开发与构建](docs/开发与构建.md) · [更新记录](CHANGELOG.md)

1. 安装并启动 **Docker Desktop**，使用 Linux 容器模式。按 Docker 官方许可与系统要求配置。
2. Windows 解压**整个文件夹**，双击 `CCBOX.exe`；Mac 解压后将 `CCBOX.app` 放入“应用程序”。
3. 在 CCBOX 选择独立空间，添加自己的项目文件夹，填写代理并测试。
4. 保持默认“沙箱开发”，点击“打开 / 恢复 VS Code”。首次构建、下载编辑器需要等待。
5. 确认自己的项目可信，在沙箱 Claude 面板或终端完成官方授权；授权网页使用沙箱浏览器。

Mac 版本使用原生 ARM64 构建，默认 ad-hoc 签名，**尚未 Apple 公证**；首次启动可能出现系统确认提示。请核对来源和 SHA-256 后按 macOS 提示操作，不要关闭系统整体安全检查。

## 两种模式

| | 沙箱开发（默认） | 本机开发（可选） |
|---|---|---|
| Claude、登录、VS Code | 容器 | 仍在容器 |
| 文件编辑 | 显式挂载的项目 | 同一共享项目 |
| 编译 / 测试 | 容器工具链 | 可调用本机工具链 |
| 本机执行权限 | 未建立本机执行桥 | 每条命令在 CCBOX 确认后执行 |
| 模型请求网络 | 容器代理通道 | 保持原容器代理通道 |
| 本机命令网络 | 不适用 | 本机网络，不自动使用模型代理 |

**本机模式的工作目录不是系统沙箱。** 获批命令、构建脚本及其依赖以当前系统用户权限运行，可能读取本机文件与环境信息，输出也可能进入模型上下文。仅对可信项目启用；需要严格隔离时使用沙箱模式或独立系统用户 / 虚拟机。

## 功能

- 多账号空间：独立 Compose 项目、home 卷、浏览器与编辑器资料；不复制宿主账号。
- 多项目：主项目与附加目录，支持只读挂载。
- HTTP / HTTPS / SOCKS5 代理；SOCKS 目标域名由代理侧解析，连接失败不自动回退直连。
- 沙箱桌面：恢复最小化 VS Code、打开 Claude 面板、明确确认后传送文字和图片。
- 本机工具：Docker 标准输入输出桥接 MCP，不开启宿主 TCP 服务，不挂载 Docker socket。
- 数据迁移：配置目录可选择；Docker 镜像和登录卷由 Docker Desktop 管理。
- 停止后保留项目与登录卷；删除卷、恢复出厂和跨机器搬迁是另外的操作。

## 网络与数据提醒

“代理配置正确”“代理连通”“实际模型流量已审计”是不同层次。基础镜像和构建依赖使用 Docker 的下载网络；本机开发命令使用本机网络。工具数据备份不包含 Docker 命名卷，也不等于完整账号备份。

代理测试会向 IP 查询服务发起请求；运行 Claude、下载编辑器和安装扩展分别联系对应上游。具体边界见[架构文档](docs/架构与边界.md)。

## 仓库结构

```text
windows/        Windows 图形应用、运行组件与测试
macos/          Apple Silicon 适配、钥匙串及打包测试
tools/          源码检查、依赖许可收集
docs/           中文文档
.github/        双平台构建和手动发布
```

首次开源保留两套经过测试的平台源码，避免在发布整理时重写凭据和启动逻辑。共同逻辑变更请同步两端；后续再逐步提取公共模块。

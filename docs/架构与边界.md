# 架构与边界

## 沙箱路径

```text
宿主 CCBOX ── Docker CLI ── 创建/管理独立空间
宿主浏览器 ── 回环桌面端口 ── gateway ── 沙箱远程桌面
沙箱 Claude / VS Code / Firefox
    └─ HTTP CONNECT 本地桥 ── Unix socket 卷 ── gateway ── 所选代理 ── 服务
```

沙箱配置为非 root、只读根、丢弃 capabilities、no-new-privileges、`network_mode: none`。
只读的 IPC 卷用于代理 socket；home 与 desktop 命名卷、临时目录和显式项目挂载按用途可写。
网关与沙箱分离；桌面发布端口默认仅绑定 127.0.0.1，需要会话令牌。
不要自行映射到公网或跳过桌面认证，也不要把 Docker socket、整个用户目录挂载进沙箱。

SOCKS5 目标域名经代理解析；代理服务器本身的域名仍由网关所在网络解析。无网络接口的沙箱不通过宿主物理网卡自行直连。Firefox 禁用 WebRTC；这不等于对任何新增工具、任意改过的 Compose 或网关漏洞作出保证。

Electron 为容器兼容以 `--no-sandbox` 启动，意味着不使用 Electron 的内层沙箱；外层 Docker 边界仍保留。同一容器用户下的应用互信，可能读取该空间账号文件。容器不是虚拟机，也不是防逃逸或匿名性保证。

## 本机执行路径

```text
容器 Claude ── ccbox-host MCP ── 临时 Unix socket relay
    └─ Docker exec stdin/stdout ── CCBOX 审批 ── 本机 PowerShell / zsh
```

每次会话生成随机 socket 和令牌；连接绑定不可变容器 ID、空间与项目。无宿主 TCP 监听；不通过 SSH，也不向容器暴露 Docker 管理 socket。
`host_info` 返回工具路径；`host_run` 每次人工确认后执行。只读项目不支持本机模式，因为宿主命令不受容器挂载的只读属性限制。

本机执行拥有当前用户权限。环境变量使用白名单，不主动导入宿主 Claude 凭据、SSH Agent 或云令牌；但脚本仍可以自行读取有权访问的文件、调用系统程序、访问本机网络。工具输出可进入模型上下文。命令获批后不存在“只可访问工作目录”的内核限制。

托管任务使用 Windows Job Object / POSIX 进程组控制退出，最长一小时；输出保留末尾 24000 字符，不自动重试。切换或断开会取消托管任务；恶意程序主动脱离进程组等情况不在强隔离保证内。

## 哪些数据在哪里

| 内容 | 存储位置 / 边界 |
|---|---|
| Windows 配置 | 工具目录的 data，或用户选择的迁移目录；位置指针在工具目录 |
| Mac 配置 | `~/Library/Application Support/CCBOX`，或迁移目录 |
| Windows 代理凭据 | 当前 Windows 用户 DPAPI 加密保险库 |
| Mac 代理凭据 | 登录钥匙串；磁盘配置只保存引用 |
| 运行时网关凭据 | 空间专用受限 active 文件，停止时清理；运行期不是加密内存保险箱 |
| Claude / 浏览器 / 编辑器登录 | 每空间独立 Docker home 卷 |
| 项目 | 用户明确选择的宿主目录，可读写或只读共享 |
| 本机开发模式 | 单独的 development.json，不替换原账号配置 |

不同空间共享同一个宿主、Docker daemon 与可能相同的项目目录。同一个项目挂载给多个账号意味着共享文件；本机模式共用系统用户。需要严格多用户安全边界时应分开 OS 用户、虚拟机或主机。

## 网络范围

- **模型和沙箱应用**：配置的容器代理路径；失效时不自动直连。
- **镜像和构建依赖**：Docker 构建网络，不等于沙箱代理路径。
- **本机命令**：本机网络，不自动继承模型代理；返回的 IP / 系统信息可能出现在模型上下文。
- **代理测试**：目前联系 `api.ipify.org` 与 `ipwho.is` 查询出口与地区，结果依赖外部数据库。
- **编辑器和扩展**：安装时联系 Microsoft 等上游；Claude 联系 Anthropic 服务，各自政策适用。

测试采用空白临时目录和模拟凭据，CI 不登录真实 Claude、不读取真实钥匙串、不发送付费模型消息。进程检查和配置检查不是对每个模型请求的实时网络审计。

# 让沙箱桌面铺满窗口

从 0.3.3 开始，沙箱 VS Code 页面默认选择 **自动铺满 + 高清**。直接调整浏览器窗口大小，或点击右上角 **全屏工作**，稍等片刻，桌面会重新布局，不需要每台电脑手填分辨率。

## 旧环境第一次升级

1. 保存沙箱 VS Code 中的文件，等正在运行的任务结束。
2. 更新 CCBOX 安装包，保留原有数据目录。
3. 在 **运行与维护 → 准备 / 修复编辑器** 中确认升级。会先构建显示组件，然后重启当前沙箱；浏览器、终端、编辑器会关闭，但项目、账号登录卷和代理配置保留。
4. 重新打开沙箱 VS Code，刷新旧浏览器页面。底部显示 **已适应窗口** 即表示已匹配。

新建环境直接使用新组件。其他账号空间相互独立，使用时按需升级，不批量重启。

## 顶部三个显示选项

| 选项 | 什么时候用 |
|---|---|
| **自动铺满**（默认） | 根据页面剩余空间改变沙箱桌面的实际分辨率。宽屏不再被固定画幅限制；最大 3840 × 2160 |
| **跟随画面** | 不改变桌面分辨率，只等比显示。两台设备同时看同一账号环境时，旁观设备可选它 |
| **原始大小** | 不主动调整分辨率、不缩放画面。窗口小于桌面时滚动查看，适合检查文字 |

**画质：** 默认「高清」使用 noVNC 的最高质量等级；网络慢或操作卡顿时选择「流畅」。高清仍可能使用有损编码，不是无损视频；清晰度也受网络、系统缩放和浏览器缩放影响。

## 常见问题

**为什么 1920 × 1080 的窗口，底部显示的高度小于 1080？**

工具栏、底部状态和浏览器自身界面占用空间，桌面只使用剩余的绘图区。这是正常的，不会裁掉代码。

**Retina / 系统缩放 150% 的屏幕会怎样？**

按页面的 CSS 可用尺寸匹配，而不是强制乘以物理像素倍数，以免字变得很小或大量增加传输。此版本不承诺 Retina 物理像素一比一；文字大小可以在沙箱 VS Code「查看 → 外观 → 放大」中调整。调整的是容器内编辑器，不是宿主系统设置。

**超大屏还是有空白？**

桌面上限为 3840 × 2160，超过上限会居中。未最大化的应用也可能留出桌面背景：VS Code 可点击「恢复 VS Code」最大化；浏览器等其他应用使用各自的最大化按钮。不会强制拉伸画面。

**显示“尚未匹配窗口”怎么办？**

先等窗口停止变化，再确认顶部为「自动铺满」。旧环境需执行上面的组件升级；断线时点「重新连接」。仅更新网页不会让旧的固定尺寸 Xvfb 具备动态分辨率能力。

**两台电脑会互相影响吗？**

同一账号空间只有一个共享桌面，最后调整窗口的活动设备决定分辨率；旁观设备选「跟随画面」。隐藏或失焦页面暂停主动调整。需要完全独立的桌面，请选择不同账号空间。

**会额外读取电脑环境信息吗？**

页面为调整显示会将绘图区宽高发送给沙箱 VNC 服务，没有新增宿主字体、语言、时区或设备清单采集。容器内应用可观察到其虚拟桌面分辨率；这不是绝对匿名承诺。现有网关鉴权、容器网络隔离、代理配置和手动剪贴板传送机制保持不变。

## 实现和测试说明

- 使用 [TigerVNC 的原生 SetDesktopSize 支持](https://manpages.debian.org/bookworm/tigervnc-standalone-server/Xtigervnc.1.en.html)，VNC 只监听容器回环地址，经过现有鉴权网关访问。
- 页面使用 [noVNC 公开 API](https://github.com/novnc/noVNC/blob/v1.3.0/docs/API.md)，不依赖私有字段；响应式绘图区设有尺寸上限和调整延迟。
- 独立 Linux 测试环境验证真实 X11 分辨率与画布一致：1366、1920、2560、3440、3840、超上限与窄屏；并覆盖全屏、重连、画质选项、跟随 / 原始大小不主动调整、显式剪贴板。未在测试中使用真实 Claude 账号或发送模型请求。
- Windows / Mac 原生 CI 负责各平台单元测试及打包自检，不代表在所有型号屏幕上做过人工实测。

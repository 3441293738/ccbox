# 局域网访问

从 0.3.1 起，可以在另一台电脑的浏览器里使用当前沙箱桌面。默认仍然只开放本机 `127.0.0.1`，每个独立空间分别开启、使用不同端口和访问口令。

## 三步开启

1. 在 CCBOX 首页选好空间，点击 **局域网访问**。也可进入「项目文件」展开同名设置。
2. 勾选「允许局域网访问当前空间」，点击「检测本机地址」，核对使用的是连接家庭 / 办公网络的网卡。点击 **保存并应用访问设置**，确认短暂重连。
3. 点击 **查看连接信息**，分别复制地址和访问口令。在另一台设备的浏览器打开地址，输入口令进入桌面。

例如主机地址是 `192.168.1.10`、当前空间端口是 `6080`，另一台设备访问 `http://192.168.1.10:6080/desktop.html`。不要把 `127.0.0.1` 发给另一台电脑：它指向访问者自己的电脑。

访问口令随机生成，**不是 Claude 账号密码**。它保存在当前环境的凭据保险库中；不会把代理密码发给访问者，也不会把访问口令放进局域网 URL 或操作日志。需要撤销已分享的访问权限时，点击「重置访问口令」；已有连接会断开，旧口令失效。

## 会不会清空环境？

不会因这项操作清空。运行中应用访问设置只重新创建当前桌面网关，不停止 sandbox 容器，不删除 home 卷，VS Code 和账号登录保留。网页需要重新连接。尚未启动的空间保存设置后，下次启动时生效。

如果同时修改了项目、代理或端口，先保存其他设置。端口有待应用修改时，按提示先重启环境；局域网按钮不偷偷替你应用其他配置。

## 安全与权限

- **这是共享同一个完整桌面，不是多用户权限系统。** 持有口令的人可以操作 VS Code、终端、浏览器，读取 / 修改已共享项目，使用当前 Claude 登录与额度。多人操作会互相影响。
- 本机开发模式的权限提示仍显示在运行 CCBOX 的主机上；远端桌面不是独立的本机命令审批入口。
- 当前局域网入口为 **HTTP，传输不加密**。口令鉴权不防网络窃听。仅在可信局域网使用，不做公网端口转发；跨不可信网络请另设受控 VPN 或经过正确配置的加密隧道。
- 仅绑定你选择的私有 IPv4 地址，同时保留本机入口；不绑定 `0.0.0.0` 或 IPv6。更换 Wi-Fi / DHCP 地址后要重新检测并应用。
- 仅开放桌面端口，不开放模型代理端口；sandbox 的 `network_mode: none` 和原有出站代理路径不变。
- 工具不自动更改防火墙。请保留防火墙保护，只允许需要的端口与可信来源。

## 连接不上时

| 现象 | 检查方法 |
|---|---|
| 超时 / 打不开 | Docker 与当前空间是否正在运行；地址是否为主机的内网 IP；是否已点击「保存并应用访问设置」 |
| 同一 Wi-Fi 仍不通 | 检查是否为访客网络、路由器是否开启客户端隔离；设备之间需能够互访 |
| Windows 被拦截 | 在 Windows Defender 防火墙高级设置中，仅为当前 TCP 桌面端口建立入站规则，限定「专用」网络配置文件及「本地子网」远程范围；公司设备由管理员处理 |
| Mac 被拦截 | 检查 macOS 防火墙对 Docker Desktop 后端的入站许可，遵循管理员策略，不关闭整体防火墙 |
| 显示访问口令页 | 正常，输入此空间的访问口令；不同空间的口令不通用 |
| 提交口令后出现 403 / 503 | 更新到 0.3.2 或更高版本，再重新打开 `/login`；旧页面强制刷新。持续异常时查看网关诊断，勿发送访问口令 |
| 口令错误 / 尝试过多 | 从 CCBOX 重新复制当前生效口令；频繁失败后等待一分钟重试 |
| 能显示页面但桌面不连接 | 检查网关和 sandbox 状态、浏览器是否允许 WebSocket；确认没有使用旧端口或自行配置的反向代理 |
| 粘贴文字 / 图片 | 继续使用顶部「发送文字 / 图片」，手动粘贴或选文件，再在沙箱按 Ctrl+V；HTTP 页面不承诺浏览器的自动剪贴板读取能力 |

关闭访问：取消勾选并点击「保存并应用访问设置」。其他设备断开，本机入口继续使用。

Docker 官方参考：[端口发布与地址绑定](https://docs.docker.com/engine/network/port-publishing/)、[Desktop 网络与防火墙](https://docs.docker.com/desktop/features/networking/)。

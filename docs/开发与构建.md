# 开发与构建

需要 Git、带 Tk 的 Python 3.12，以及对应的原生系统。发行包本身自带 Python。当前 Windows x64 与 Mac ARM64 分别构建；不在 Windows 上伪装产出 Mac 应用。

从仓库根目录执行下列命令。先创建虚拟环境并激活（Windows：`py -3.12 -m venv .venv` 后运行 `.venv\Scripts\Activate.ps1`；Mac：`python3 -m venv .venv` 后 `source .venv/bin/activate`）。

## Windows

```powershell
$env:PYTHONUTF8='1'
python -m pip install -r windows/requirements.txt pyinstaller==6.22.3
python -m unittest discover -s windows/tests -p 'test_*.py' -v
python windows/ccbox.py
# 打包前关闭源码窗口；输出目录必须为空。
python windows/packaging/build_windows.py --output windows/release
```

输出 `CCBOX-windows-x64.zip`，解压后保留 EXE 旁的 runtime 等完整文件。构建不会替换已有安装、使用真实账号或启动 Docker 工作负载。

## M 系列 Mac

```sh
python -m pip install -r macos/requirements.txt pyinstaller==6.22.3
python macos/tests/run_tests.py
python macos/ccbox.py
# 使用原生 ARM64 Python，不使用 Rosetta x64。
python macos/packaging/build_macos.py --output macos/release
```

测试 runner 用内存钥匙串替身，不读写真实 Keychain。打包检查 Python 架构、Tk、应用与归档解压后的自检、ARM64 和代码签名完整性。默认 ad-hoc；设置 `CCBOX_SIGN_IDENTITY` 可使用已安装证书，但此流程不完成 Apple 公证。

`packaging/*.spec` 是内部打包配置，请通过 build 脚本调用（脚本会先收集第三方许可）。许可源来自安装包元数据及与运行时版本对应的 Python / Tcl / Tk 上游 HTTPS 文件，需要网络。

## CI 与发布

- main push、PR 和手动触发执行双平台构建；构建 token 只读，不使用用户代理、模型账号或 SSH 凭据。
- Actions 的“测试、打包与发布”选择 Run workflow，`release_tag` 留空只打包。
- 发布时仅 main 分支，填写与 VERSION 一致的标签（例如 `v0.3.0`）。两端成功后验证 commit、SHA-256 和自检报告，再创建草稿、上传产物并转为正式 Release。
- 已有标签/Release 不自动覆盖；失败草稿需要维护者先检查后处理。
- Python 依赖有版本约束；Docker 基础镜像和 `latest` 上游工具仍可能变化，当前不承诺位级可复现构建。

## 验收层次

1. 源码卫生与单元测试（临时目录、虚构凭据）。
2. 打包 / 解压后的 GUI 控件与资源自检，不等于人工视觉验收。
3. 真机 Docker、系统保险库、项目挂载、停止后保留和权限提示，使用单独测试空间。
4. 真实账号与模型联网需另行明确授权；CI 不执行、不消费额度。

`verification.json` 只记录该次构建实际完成的层次。新增功能需按影响补测试，并明确未验证项。

# 多个账号，多个同时运行的沙箱

从 0.3.5 起，打开 CCBOX 默认进入「账号空间」。Windows 和 M 系列 Mac 的操作相同。

## 先认识一张卡

| 页面上的内容 | 含义 |
|---|---|
| 空间名称 | 自己填写的备注，例如“工作账号 A”；不自动读取或验证 Claude 账号身份 |
| 当前 | 当前 CCBOX 设置页和后续操作所属的空间，不表示只有它能运行 |
| 运行中 | 检测到沙箱运行且网关健康；不等于已登录 Claude，也不证明代理出口正常 |
| 已停止 / 未启动 | 点击“启动并打开”继续；已保存的登录卷与项目不会清空 |
| 启动异常 / 尚未就绪 | 容器退出、未完成启动或健康检查未通过；进入“检查与修复”查看 |
| 未连接 Docker | 暂未查到状态，不能据此判断容器已停止；启动 Docker 后刷新 |
| 桌面端口 | 该空间的独立网页入口，新空间自动分配不同端口 |

状态页每 5 秒后台刷新；离开列表后停止定时刷新。刷新只查询 Docker，不测试代理、不发模型消息、不读取账号令牌。

## 第一次新增账号

1. 点击右上角 **新建账号空间**，填写容易区分的备注。
2. 按“当前空间”的提示 **选择项目 → 填写代理**。新建不会复制旧空间的代理、登录或项目。
3. 点击 **打开 / 恢复 VS Code**。首次需要准备镜像和编辑器，等操作记录显示完成。
4. 在这个沙箱自己的 Claude 面板中登录。授权使用沙箱浏览器。
5. 回到“账号空间”，为下一个账号重复以上步骤。

管理任务（例如首次安装、停止）逐个处理；已经运行的其他容器继续工作，不会因你准备另一个账号而停止。

## 两个账号同时用

- 对账号 A 点击 **启动并打开**，准备好后，对账号 B 做相同操作。
- A、B 会在不同桌面入口运行，可保留两个浏览器标签页。
- 在卡片点击 **打开 VS Code** 会切到对应空间并打开其编辑器；如果需要更换项目，先点 **设置 / 项目**。
- 已经打开的标签页始终属于原账号空间，不会跟随 CCBOX 的下拉框偷偷切换。
- 只想停止 B，在 B 的卡片点 **停止**，核对确认框里的名称。A 不受影响。
- 多个沙箱会增加 CPU 和内存占用。可分别在“项目文件 → CPU 与内存”调整资源；修改后按提示应用。

## 哪些资料分别保存？

各空间保留不同的 Compose 项目标识、home 登录卷、浏览器资料、编辑器配置、代理凭据、桌面访问口令及端口。重命名只改备注，停止不会删除卷。

**共享项目是例外**：若把同一个宿主目录挂载给 A 和 B，两边可读写同一批文件。需要独立开发时，选择不同目录或 Git worktree；不要同时修改同一工作副本。

**本机开发也是例外**：它使用宿主机当前用户权限，不是独立系统沙箱。切换账号或项目会断开本机执行通道并停止托管任务；新账号需要重新确认连接，每条命令仍逐次批准。

## 从旧版更新

直接替换程序与配套运行文件，保留数据目录、保险库和 Docker 卷。原账号空间会自动出现在列表，无需重新新建或重新登录。

若旧账号曾报 `ModuleNotFoundError: clipboard_transfer`，新版本已补齐网关代码的只读挂载依赖。启动时使用新配置即可；不要删除 home 卷。旧显示镜像仍可能需要按提示升级，先保存该空间的工作，再确认重启。

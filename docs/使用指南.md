# 使用指南

## 第一次使用

先启动 Docker Desktop。Windows 使用 Linux 容器，Mac 安装 Apple silicon 版。图形应用已内置 Python；使用发行包无需自行安装 Python。

首页选择一个独立空间。在“项目文件”选择一个项目目录，避免整块磁盘、用户主目录、工具数据目录。需要多个项目时逐个添加附加文件夹；只需参考的项目可设为只读。

在“代理设置”选择 HTTP、HTTPS 或 SOCKS5，填写服务地址和端口；用户名密码按服务提供者要求填写。仅在本地输入，勿粘贴到公开 Issue。测试成功后保存，返回首页开始开发。

第一次下载较慢。配置已保存、Docker 已运行，不表示沙箱已经创建。查看操作记录，等待明确的完成提示，不要在构建期间关闭 Docker。

## 登录与账号切换

1. 选择目标空间，再打开其沙箱 VS Code 或 Claude 终端。
2. 按 Claude 官方流程登录。授权网页应在该空间的沙箱 Firefox 中打开；不要把授权链接交给宿主浏览器。
3. 同一容器 home 卷中的 CLI 与插件可沿用有效会话；过期时重新授权。
4. 新空间从空白资料开始，需要独立登录。选择器不会把已有窗口的账号改成新账号；旧窗口仍属于原空间。

“本机 VS Code”是兼容入口，界面仍在宿主；“沙箱 VS Code”才是整个编辑器运行在容器的入口。

## 本机开发：使用已有工具链

1. 保存工作，选择账号空间与当前项目。
2. 模式切换为“本机开发”，阅读并确认权限提示，再打开编辑器。
3. 第一次连接后，新建 Claude 会话；旧会话未出现 `ccbox-host` 时，在 MCP 管理界面重新连接或重载窗口。
4. 可输入：`请用 ccbox-host 的 host_info 查看工具，再用 host_run 运行项目测试。`
5. 每条本机命令会在 CCBOX 显示，核对后选择“仅执行这一次”。普通 Bash / 沙箱终端仍在容器，不会自动改成本机执行。

CCBOX 需要保持打开。切换账号、项目或模式及关闭 CCBOX 会断开本机通道并停止托管任务，不回滚已完成的修改。一次连接一个账号的一个项目；同数据目录下项目锁避免多连接同时使用，但不是系统级账户隔离。

## 恢复窗口与剪贴板

- 最小化：点沙箱页面顶部“恢复 VS Code”。编辑器已关闭时，回 CCBOX 点“打开 / 恢复 VS Code”。
- 文字：点“发送文字”，粘贴并确认，再在沙箱输入框按 Ctrl+V。
- 图片：点“发送图片”，在专用输入区粘贴截图或选择文件，确认预览后发送，再 Ctrl+V。不会自动发送模型请求。
- 宿主剪贴板不自动读取或同步。文字上限 1 MB；图片上限 12 MB，每次一张，过大尺寸会缩小。

## 停止、更新与备份

“停止当前空间”保留命名卷，重启不是全新的账号。新增挂载或修改代理后按界面提示保存并重新启动当前空间；停止前保存工作。

更新 Windows 版先关闭 CCBOX，保留数据目录与 `storage-location.json`，将新包的程序及运行组件合并到原安装目录，不要用空目录覆盖旧 `data`。Mac 替换 `.app` 不主动删除 Application Support 数据；钥匙串仍需保留。

配置目录迁移使用工具按钮，会保留旧目录备份；Docker 数据磁盘迁移请在 Docker Desktop 中操作，影响该 Docker 实例的所有项目。工具配置、系统保险库、Docker 命名卷和项目文件需要分别备份。Windows DPAPI 与 Mac 钥匙串资料不自动跨设备迁移。

旧沙箱缺少桌面或剪贴板组件时使用“检查与修复 → 准备 / 修复编辑器”，保存工作后确认重启；已有桌面组件的环境启用本机模式不需要单独重建镜像。

## 常见问题

- **找不到 Docker**：先启动 Desktop，再检查 Linux 引擎与 Compose；Mac Finder 启动会补充常见 Docker CLI 路径。
- **证书验证失败**：核对系统时间、代理协议与证书链；Mac 发行包自带根证书包。不要通过关闭证书检查解决。
- **工具版本没找到**：本机模式只检测路径，不执行 shell 启动脚本；可以在获批命令中使用完整路径或初始化自己的版本管理器。
- **代理测试成功但 Claude 未响应**：还需检查账号登录、额度、服务状态与实际请求路径。配置检查不自动消耗模型额度。
- **macOS 首次打开被拦截**：核对发行页与校验值，按“系统设置 → 隐私与安全性”提示操作。当前包未公证，受管理设备遵循管理员策略。
